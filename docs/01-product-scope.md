# 产品范围与验收目标

## 产品定义

MINFO 面向需要整理本地音乐文件信息的个人用户。一次操作只围绕一个音频文件展开，目标是让用户明确知道：读到了什么、哪些字段能改、导出后会得到什么，以及哪些信息可能无法被目标格式保存。

第一版不建立音乐库、不扫描磁盘目录、不提供云同步、登录、分享链接或服务端转码。浏览器读取由用户主动选择的文件，源文件始终保留在用户设备上。

## 用户主流程

1. 用户通过文件选择器或拖拽放入一个音频文件。
2. 应用先做轻量校验，再解析格式、技术属性和可读取的标签。
3. 页面以表单回显可编辑元数据，以只读区展示固定技术信息。
4. 用户编辑字段、替换或移除封面、编辑歌词，并选择原格式或新的导出格式。
5. 服务层预检实际可用的引擎、目标格式能力和可能丢失的元数据。
6. 用户确认后，应用在浏览器本地生成一个新文件并触发下载；源文件不被修改。

## 首版功能范围

### 输入

- 文件选择和拖拽均接受 `audio/*`，同时允许以扩展名补充识别 MIME 缺失或错误的音频文件。
- 每次只处理一个文件。再次选择文件会请求用户确认放弃尚未导出的编辑。
- 文件名、浏览器报告的 MIME、字节数和扩展名只能作为预检线索。最终格式以解析结果为准。

### 可编辑元数据

首版界面统一提供以下字段。服务层必须按输出容器的可表达性决定写入或提出风险提示：

| 分组 | 字段 |
| --- | --- |
| 基本信息 | 标题、艺术家、专辑、专辑艺术家、流派、发行年份、评论 |
| 编排信息 | 曲目号、曲目总数、碟号、碟总数、作曲者 |
| 富内容 | 内嵌封面、歌词原文（纯文本或含 LRC 行级时间标签） |

歌词字段始终保存用户输入的原文。界面会自动识别 LRC 式行级时间标签：检测到有效时间标签时以时间轴辅助预览，未检测到时以保留换行的纯文本预览。该展示解析不会改写原文，也不把 LRC 自动转换为 ID3 SYLT 等同步歌词编码；翻译歌词、多语言歌词槽位和逐词时间轴仍不在首版承诺范围。

封面新增或替换时只接受 PNG、JPG/JPEG、GIF 和 WebP。首版限制为：文件不超过 **2 MB（2,000,000 bytes）**，宽和高均不超过 **1000 px**。该规则只限制用户新选择的封面，不会因为源文件内嵌封面超出限制而删除或修改源封面。

### 固定技术信息

以下信息在输入文件详情中只读：原始文件名、扩展名、探测到的容器和编解码器、文件大小、时长、采样率、声道数、比特率或无损标记。任何无法可靠取得的项目显示“未能读取”，不以推测值填充。

### 导出

- 默认输出为输入文件的原扩展名。
- 内置候选项：`mp3`、`aac`、`flac`、`m4a`、`wma`、`wav`、`ogg`、`ape`、`amr`、`mid`、`alac`、`oga`。
- 支持输入其他扩展名，但手动输入只是提出“目标请求”，不是绕过能力校验的承诺。
- 原格式和新格式都必须经过能力预检。不可用时解释原因，保留用户编辑，并提供“改用 MP3”作为可一键采纳的兜底建议。
- 导出文件为新下载，不覆盖原始文件。

## 非目标与边界

- 不承诺任意源格式可以转为任意目标格式。
- 不承诺音频指纹、在线曲库匹配、自动补齐封面或歌词。
- 不把浏览器原生的播放支持误认为文件解析或标签编辑支持。
- 不将 MIDI 视作已编码的波形音频。它是事件序列，不能在没有音源/合成策略的前提下可靠转换为 MP3 等音频文件。
- 不允许静默丢弃封面、歌词或多值标签。目标格式不支持时，用户必须在导出前获知。

## 验收标准

首个可发布版本至少满足：

1. 用户可用鼠标、触摸和键盘完成选择、编辑、格式选择和导出。
2. 对可支持的样本文件，显示真实的基础标签、封面和时长；读取失败有可理解的原因。
3. 不可编辑字段没有编辑控件，编辑字段都有名称、帮助文本、校验反馈和恢复原值的途径。
4. 输出格式不支持、引擎不可用、内存不足、取消或转换失败时，页面不丢失编辑内容，也不使用模糊的“失败”提示。
5. 每次导出都在客户端完成，且清楚告知用户源文件未上传、未覆盖。

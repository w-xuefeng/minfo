# 元数据与格式策略

## 规范化原则

界面使用一个与格式无关的“编辑草稿”，而不是直接把任一文件格式的字段名暴露给用户。读取时，适配器将源标签映射到草稿；导出时，适配器按照目标容器映射回可支持的原生标签。

草稿字段包含值、原始值、读取状态、验证状态和写入可行性。空字符串、未读取、源文件中不存在、目标格式无法表示是四种不同状态，必须分别展示和处理。

读取优先级是浏览器原生文件/播放技术属性，随后才是 Worker 中 `ffprobe` 的容器级探测。标题、艺术家、专辑、封面、歌词和格式特定技术属性以 `ffprobe` 的结构化结果为权威来源；原生属性只能作为快速补充和交叉校验，不能覆盖已探测到的真实容器信息。

## 字段处理规则

| 字段类型                   | UI 编辑方式                                                       | 导出策略                                                                                                                                                                                  |
| -------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 单值文本                   | 单行输入                                                          | 写入目标格式等价字段；没有可执行浏览器目标时列为不可执行，否则列出副本影响并要求确认                                                                                                      |
| 多值流派/艺术家/专辑艺术家 | 可增删的标签输入，导出前保留顺序                                  | 依据目标格式的分隔规则转换，不能无损表达时列为“结构将扁平化”，确认后才写入                                                                                                                |
| 发行日期                   | 受控 ISO 日期输入                                                 | 仅接受 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`，不接受时间、时区或自由文本                                                                                                                        |
| 曲目/碟号                  | 数字和总数成对输入                                                | 不允许负数或零；缺失总数可以只写编号                                                                                                                                                      |
| 封面集合                   | 按 `front`、`back`、`disc`、`artist`、`other` 和顺序管理          | 新增/替换仅接受 PNG、JPG/JPEG、GIF、WebP，最大 2 MB（2,000,000 bytes）、1000×1000 px；目标的表单能力配置禁用时保持只读可见并说明原因；若目标无法容纳全部图片，逐张选择保留或省略          |
| 歌词槽位                   | 按语言独立的多行编辑器；每种语言一个槽位，自动识别 LRC 式时间标签 | 槽位集合是歌词导出清单：先清除已识别的源歌词标签/帧，再写入第一个槽位的普通 `lyrics` / `lyrics_language` 与其余槽位的 `lyrics-{language}`；LRC 检测只影响展示，首发不生成新的同步歌词编码 |
| 评论                       | 多行文本                                                          | 需保留编码与语言差异的诊断；首版只编辑一个默认评论槽位                                                                                                                                    |

### 封面替换校验

封面校验仅发生在用户新增或替换封面时，不回溯拒绝源文件已内嵌的封面。允许的实际媒体类型为 `image/png`、`image/jpeg`、`image/gif` 与 `image/webp`，对应常见扩展名为 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`。

| 规则     | 首版限制                       | 失败处理                                           |
| -------- | ------------------------------ | -------------------------------------------------- |
| 文件格式 | PNG、JPG/JPEG、GIF、WebP       | 保留当前有效封面和表单草稿，提示用户选择允许的格式 |
| 文件大小 | 不超过 2 MB（2,000,000 bytes） | 显示当前大小和上限，不读取为封面预览               |
| 图像宽高 | 宽和高均不超过 1000 px         | 显示实际尺寸和允许范围                             |

校验顺序为：大小与声明类型的快速检查、文件签名检查、图像头尺寸检查、受控解码预览。扩展名和浏览器声明的 MIME 只是提示，不足以作为通过依据。GIF 和 WebP 被作为允许的图片格式处理；若目标容器或标签写入器不能保留图片类型、顺序或全部图片，预检必须逐项列出，用户先选择保留或省略，不能自动转换或静默移除。

### 非编辑私有元数据：验证后的 XMP `PRIV`

ID3 `PRIV` 帧可承载厂商自定义二进制或结构化数据。`owner-identifier = XMP` 只能说明该帧自称使用 XMP；它不是签名，也不能证明由某个厂商或软件写入。只有 owner 为 `XMP`、完整私有数据不超过 64 KiB、可按 UTF-8 或带 BOM 的 UTF-16 解码，并通过 XML 解析确认文档根元素为 `xmpmeta` 且命名空间为 `adobe:ns:meta/` 时，MINFO 才把它当作已验证的 XMP 包。这不是音频或容器错误，也不是可安全映射为通用文本字段的标签。读取器此时将解析器的 `Unknown PRIV owner-identifier: XMP` 改为非阻塞信息：**“检测到 XMP 私有元数据；MINFO 暂不编辑，导出后不承诺逐字保留。”**

`x:xmptk`、`xmp:CreatorTool`、命名空间中的 `adobe` 等只是 XMP 包内可写的格式或工具线索，不能作为写入应用、开发商或文件来源的可信归因；MINFO 不显示此类归因。该载荷不进入“原始文本标签”编辑器，不计作未知标签风险，也不单独要求“我已知晓，坚持导出”。MINFO 不创建、修改或承诺字节级保留它；同容器重封装或跨容器导出时，通用封装器可能保留、重写或省略它。仅有 `XMP` owner、无法解码或未通过结构校验的载荷仍按未知或容器特定标签处理，继续保留警告，并在跨容器转换计划中保留对应风险确认。

### 歌词时间标签检测与写入

每个歌词槽位的原文都是该槽位唯一的可编辑和导出来源；完整槽位集合也是唯一的歌词导出清单。解析服务在导入、粘贴、输入停止后和恢复原值后分别重新检测，不会删除标签、合并行、重排时间或替换换行符。

| 展示状态   | 识别条件                                   | 展示规则                                                                   |
| ---------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| 带时间标签 | 至少一行以一个或多个有效 LRC 时间标签开头  | 生成时间轴行，时间与歌词内容分列展示                                       |
| 混合       | 存在有效时间标签，且还有非空行没有时间标签 | 时间轴保留带标签的行，未带标签行作为上下文显示，并提示“部分行没有时间标签” |
| 纯文本     | 不存在有效时间标签                         | 按原始换行分段和换行显示，不将全部内容压成一行                             |

首版识别的行级时间标签为 `[mm:ss]`、`[mm:ss.xx]`、`[mm:ss.xxx]`，其中秒数为 `00-59`，分钟数可大于 59；同一行的多个时间标签生成多个时间轴行。`[ar:…]`、`[ti:…]`、`[al:…]`、`[offset:…]` 等 LRC 元标签不视为时间标签，仍按原文保留。格式不完整或非法的方括号文本也保留为原文，不因解析失败丢失内容。

### 歌词文件导入

每个语言槽位的“解析歌词文件”只读取用户主动选择的一个本地文件，支持 `.txt`、`.lrc` 与明文 `.qrc`，大小不得超过 **2 MB（2,000,000 bytes）**。扩展名是准入条件，浏览器声明的 MIME 仅作提示；读取器接受 UTF-8（可带 BOM）和带 BOM 的 UTF-16 文本，拒绝空内容、NUL 字符、无法解码的字节和其他扩展名。所有解析在浏览器内完成，不上传或持久化歌词文件。

`.txt` 和 `.lrc` 的文本原样进入替换候选，不主动清洗换行或时间标签。明文 QRC 的 `[起始毫秒,行时长]` 行时间会转换为 LRC `[mm:ss.xxx]`，逐字 `(起始毫秒,时长)` 信息因当前草稿仅表达行级 LRC 而被移除；XML QRC 从 `LyricContent` 提取同样的明文 QRC。加密、压缩或其他无法识别的 QQ Music QRC 不是此路径的可支持输入，必须明确提示用户先在本机导出明文 LRC/QRC，不能把二进制内容写入歌词槽位。

空槽位在解析成功后可直接填入；若目标槽位已有任意非空歌词，界面必须先显示文件名、解析结果和“替换当前歌词 / 取消”的二次确认。取消、读取失败或格式不合规时，当前槽位文本保持不变；错误必须显示在该槽位附近，而不是只显示为短暂通知。

检测到 LRC 不等于目标音频格式支持同步歌词。浏览器路径将每个槽位的原文写入目标格式可表达的普通歌词字段（MP3 的主槽位通常映射为 `USLT`），但不生成新的 `SYLT` 或其他播放器专用同步歌词结构。若导入时识别到 `SYLT`，它与其他已识别歌词来源一样由槽位集合接管：导出会移除原始同步帧，并将当前槽位的 LRC 原文作为普通歌词写出。若目标格式无法保留歌词，导出预检必须按字段级风险说明副本的具体影响，并要求用户确认；不能静默丢失。

歌词槽位的身份是规范化后的小写语言码，而不是描述符或显示顺序。新增时默认 `und`；原生可创建下拉输入提供 `und`、`zho`、`eng`、`jpn`，并允许输入其他由小写字母、数字和连字符组成的语言码。每种语言只能有一个槽位，改语言或新增时与现有槽位冲突会就地报错且不改变草稿。读取到同一语言的多个源槽位时，读取层将其文本按来源顺序合并到一个槽位并给出警告；这避免界面出现两个同语言表单，但意味着之后修改该语言时无法保留原始描述符边界。

通用 FFmpeg 元数据接口不能把任意原生歌词结构重新生成为等价的语言/描述符槽位。因此 MINFO 采用明确的替换策略，而不是保留源歌词的补丁策略：导出先按读取到的原始标签标识清除所有已识别歌词来源（如 `TXXX:lyrics-eng`、`USLT`、`SYLT`、语言声明及容器别名），再写入当前槽位所需的普通标签。删除槽位就是删除该语言的已识别歌词；不会因为源文件曾有该字段而把它保留到新副本。第一个槽位写入 `lyrics` 及 `lyrics_language`；其余槽位尝试写入 `lyrics-{language}`。已验证浏览器路径以 FFprobe 的结构化普通标签为歌词内容的权威回读：文本按原样（仅统一换行符）校验，并确认每个已删除语言的已知源标签为空或不存在；不满足时取消下载。容器解析器会因原生帧、描述符和 LRC 时间精度而对同一普通标签给出不同的槽位文本表示，所以二次槽位解析只用于发现当前表单之外仍存在的额外语言，不能因它未重建或改写了已由 FFprobe 验证的当前语言文本而阻止下载。播放器对二级普通标签的识别仍有兼容性差异，预检会说明这一风险，但它不能成为保留用户已删除歌词的理由。输出容器和音频流验证仍是下载硬条件。

## 首发浏览器输出格式矩阵

浏览器输出格式控件只提供这三个经过首发验收的目标；它不是通用 FFmpeg 格式选择器。FLAC、WAV、Ogg、WMA、APE、AMR、MIDI、ALAC、OGA 和自定义扩展名不在浏览器导出路径中，但仍可在“复制 FFmpeg 命令”的本机路径中由用户自行选择和验证。

| 用户选择 | 实际容器与扩展名      | 首发策略                                                                                                                                                                   |
| -------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mp3`    | MP3 / `.mp3`          | 首发稳定目标与通用兜底选项。常见标签为 ID3；旧 ID3v1/v2.2 在编辑时可明确升级为 v2.4。                                                                                      |
| `m4a`    | MP4 音频容器 / `.m4a` | 首发稳定容器。主动转换默认编码为 AAC；同容器编辑稳定覆盖 AAC 和 ALAC-in-M4A。                                                                                              |
| `aac`    | ADTS AAC / `.aac`     | 首发稳定的 AAC 转码目标；主动选择时始终输出原始 ADTS `.aac`，不改名为 M4A。ADTS 不承载内嵌封面，因此有任一要保留或新增封面时预检会列出将从副本省略的封面，确认后仍可导出。 |

即使在此矩阵中，输出仍须由当前运行时、源文件与目标配置共同预检；产物还要通过 FFprobe 容器/音频流验证及可读元数据回读。对于用户已确认的“输入未完整探测”或“输入格式不在已验证矩阵”风险，容器与音频流验证仍是下载硬条件，但元数据解析不再作为下载否决条件。扩展名从不单独构成格式或标签保留的证明。

## 格式目录与表单能力配置

浏览器输出选项与编辑表单是两个相互引用的数据配置，而不是组件中的格式名称判断：

- 音频格式目录维护稳定格式 ID、显示名称、输出扩展名、容器说明、MIME、浏览器兜底格式和本机命令专用选项；浏览器目标与本机命令选项共用目录，但后者不因此获得浏览器支持声明。
- 表单能力配置以格式 ID 为键，为每个现有元数据字段声明 `editable` 状态和不可编辑时的用户可见原因。未声明格式不得静默继承为可浏览器导出。
- UI 只根据当前已解析目标的配置渲染禁用/只读状态；它不包含诸如“若为 AAC”之类的分支。配置未确定时，表单保持当前草稿可见，导出预检保持保守。
- AAC 的配置将 `covers` 设为不可编辑，原因说明 ADTS 无法承载内嵌封面。添加、替换、移除、移动和图片类型操作均禁用，但已有封面继续显示，避免把“不能写入”误解为“文件没有封面”。

新增格式至少需要同时完成格式目录条目、完整表单能力配置、导出预检/回读策略和样本回归；仅把格式添加到选择器不构成支持。

## 支持等级

能力服务以以下等级返回结果：

| 等级       | 含义                                                       | UI 行为                                          |
| ---------- | ---------------------------------------------------------- | ------------------------------------------------ |
| 完整支持   | 可读取或导出，当前编辑字段可保留                           | 正常导出                                         |
| 支持但有损 | 音频可导出，但明确字段无法保留、只能尽力写入或无法逐项验证 | 显示字段清单，用户确认“我已知晓，坚持导出”后继续 |
| 仅可读取   | 可查看输入，但无可用写入/转换路径                          | 禁用导出并解释                                   |
| 未支持     | 引擎、容器、编码器或输入内容不支持                         | 说明原因，提供改用 MP3 的操作                    |
| 未知       | 尚未完成检测或检测无法判定                                 | 保持导出按钮不可用，允许重试或保留草稿           |

首发“完整支持”只可用于 MP3、M4A 与 AAC 的已验证路径。MP3/M4A 承诺标准字段、封面、普通歌词、同容器流复制式导出，以及 MP3 ↔ M4A 转换；AAC 是 ADTS `.aac` 转码目标，受其容器能力约束，尤其不会无提示丢弃封面。任何路径仍须按当前文件、目标和运行时重新预检；若可生成副本但存在已知降级，确认取代阻断。

## 不可逆风险处理

- 从无损转有损、降低采样率或更改声道属于音频内容变换，必须在导出预检中说明。转码仅提供高质量、平衡、紧凑三档可版本化预设，默认高质量；预设不能暗中改变采样率或声道数。
- 当目标不能承载封面、歌词、评论或多值字段时，列出每一个受影响字段，而不是笼统称为“部分元数据丢失”。
- 原格式导出也可能因不完整源标签、非法标签或容器限制产生差异。预检无法保证时显示“可能变化”的原因。
- 输出文件名默认使用 `{源文件名} (MINFO).{实际扩展名}`，基础名可编辑但不允许路径分隔符；扩展名由实际目标锁定。
- 风险确认仅绑定当前项目的源文件身份、草稿修订、目标容器/编码、运行时清单与受影响字段；其中任一项变化都要求重新确认。

## 为什么不能只依赖扩展名与浏览器播放

扩展名可能被改名，MIME 可能为空，而同一容器可以承载多种编解码器。`HTMLMediaElement.duration` 能在媒体元数据加载后给出只读时长，但它不提供通用标签读写能力。详见 [MDN 的 duration 文档](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/duration) 与 [WebCodecs 编解码器注册表](https://www.w3.org/TR/webcodecs-codec-registry/)。

# 产品范围与验收目标

## 产品定义

MINFO 面向需要整理本地音乐文件信息的个人用户。它以顺序队列处理多个音频文件：同一时刻只运行一个媒体任务，每个项目都有独立的草稿、预检和导出结果。目标是让用户明确知道：读到了什么、哪些字段能改、导出后会得到什么，以及哪些信息可能无法被目标格式保存。

第一版不建立音乐库、不扫描磁盘目录、不提供云同步、登录、分享链接或服务端转码。浏览器读取由用户主动选择的文件，源文件始终保留在用户设备上。

## 用户主流程

1. 用户通过文件选择器或拖拽放入一个或多个音频文件。
2. 应用按顺序做轻量校验、解析格式、技术属性和可读取的标签；失败项目不阻塞后续项目。
3. 页面展示固定技术信息，并在可编辑元数据之前提供导出目标选择。
4. 用户选择原格式或新的导出格式；界面从目标格式的表单能力配置得出当前可编辑、只读和禁用的字段及其原因。
5. 用户编辑当前目标允许的字段、管理可编辑的封面、编辑歌词。
6. 服务层预检实际可用的引擎、目标格式能力、编码质量和可能丢失的元数据。
7. 用户确认精确的导出计划后，应用在浏览器本地生成新文件并触发下载；源文件不被修改。

## 首版功能范围

### 输入

- 文件选择和拖拽均接受 `audio/*`，同时允许以扩展名补充识别 MIME 缺失或错误的音频文件。
- 可一次加入多个文件；队列串行运行一个媒体任务。取消当前任务仍继续下一项，“停止队列”则取消当前项并暂停剩余项目。每项草稿独立保留。
- 文件名、浏览器报告的 MIME、字节数和扩展名只能作为预检线索。最终格式以解析结果为准。

### 可编辑元数据

首版界面统一提供以下字段。服务层必须按输出容器的可表达性决定写入或提出风险提示；UI 不得按格式名称写死分支，而是读取格式目录对应的表单能力配置。

| 分组     | 字段                                                                            |
| -------- | ------------------------------------------------------------------------------- |
| 基本信息 | 标题、艺术家、专辑、专辑艺术家、流派、发行日期、评论                            |
| 编排信息 | 曲目号、曲目总数、碟号、碟总数、作曲者                                          |
| 富内容   | 多个内嵌封面（类型与顺序）、按语言独立的歌词槽位（纯文本或含 LRC 行级时间标签） |

艺术家、专辑艺术家和流派在草稿中保持有序多值；目标容器只能表达单值时，预检会要求确认扁平化。发行日期只接受 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。评论的便利编辑器只修改明确选定的默认槽位，其他原始槽位不因读取而删除。

高级原始文本标签只在其键和值能够无歧义映射时才能获得精确写入承诺。若同一原始键出现多个槽位（常见于带描述符或语言的扩展标签），通用 `-metadata` 写入器不能单项寻址；预检会逐项说明可能合并、重排、覆盖或无法逐项回读的槽位。用户勾选“我已知晓，坚持导出”后，浏览器仍以尽力而为的通用写入生成新副本，绝不改写源文件。

只有 `PRIV` 的 owner-identifier 为 `XMP`、完整私有载荷不超过 64 KiB，且字节可解码为具有 XMP 根元素和命名空间的 XML 包时，MINFO 才将其作为已知的非文本私有元数据处理。读取层将对应解析器提示转换为非阻塞读取信息：“检测到 XMP 私有元数据；MINFO 暂不编辑，导出后不承诺逐字保留。”`XMP`、`x:xmptk` 和 `xmp:CreatorTool` 都不是签名或可信写入者证明，界面不得据此归因具体软件或厂商；仅有 owner 字符串、超限、错误编码或不符合 XMP 结构的字节仍是未知 `PRIV` 警告。已验证 XMP 不进入高级文本标签编辑器，也不单独触发导出确认、阻断读取或阻断导出；同容器重封装或跨容器转换可能保留、重写或省略它，源文件始终不受修改。

歌词按语言独立建模为可单独新增、编辑和删除的槽位；每个槽位保存自己的原文、语言码及读取到的来源说明。同一规范化语言码只能存在一个槽位，语言在保存时小写化。导入器只把**源格式读取能力配置**识别的歌词标签和帧映射到这些槽位，槽位集合是歌词的唯一事实来源和导出清单：用户删除一个语言槽位，即明确要求新副本不再保留该语言的已识别歌词。配置根据解析器给出的容器、编解码器和原生标签类型选择，绝不以文件扩展名、歌曲内容、系统语言或当前导出目标猜测。MP3 与 ADTS AAC 的 ID3 路径可读取标准歌词、语言辅助字段和语言限定普通歌词；M4A 只将 `©lyr` 映射为一份未标注的 `und` 普通歌词，且不会把自定义 `lyrics_language` 或 `lyrics-<lang>` 伪装成 M4A 的标准字段；未知来源才回退到保守的通用别名规则。读取到同一语言的多个受支持来源时按来源顺序合并并给出提示；源格式只容纳一份标准歌词而解析到额外不同槽位时，保留已读取的主槽位并给出明确警告。新增控件提供预设语言表，并允许创建符合语言码规则的其他值。每个槽位还可本地选择不超过 2 MB 的 `.txt`、`.lrc` 或明文 `.qrc` 文件导入：空槽位可直接填入，已有非空歌词必须经过二次确认才会替换。`.txt`/`.lrc` 保留可解码的原文；明文 QRC（包括 XML QRC）会降为 LRC 行级时间，逐字时间不进入草稿。加密或无法识别的 QRC、空文件、错误编码、超限或不受支持的扩展名不能改变已有歌词，界面须在该槽位就地说明原因。界面会对每个槽位自动识别 LRC 式行级时间标签，预览默认折叠，展开后以时间轴或保留换行的纯文本显示；展示解析不会改写原文。

浏览器只写普通歌词元数据，不生成新的 ID3 `SYLT`。当前槽位集合仍是新副本的歌词清单，但具体写入字段、可回读字段和降级风险由目标格式的歌词能力配置决定，而不是所有容器都强行套用 `lyrics_language` 与 `lyrics-{language}`。MP3 与 ADTS AAC 的当前 ID3v2 路径可写入并由 FFprobe 回读主歌词、MINFO 的语言辅助字段和附加语言槽位；M4A 只将主歌词 `lyrics` 映射为 iTunes 风格的 `©lyr`，不承载 `lyrics_language` 或多个 `lyrics-{language}` 槽位。M4A 因而只保留第一个槽位的歌词原文，语言身份和其他语言槽位会在预检中逐项说明、经确认后降级，而不会被伪装成完整保留或作为下载失败理由。`lyrics_language` 绝不能改写为音频流的 `language`，后者描述的是音轨语言而非歌词语言。

每次导出仍会请求清除输入中已识别的歌词标签或帧（包括语言声明、语言限定标签和已识别原生别名）。对目标格式声明为可写且可验证的字段，首发浏览器路径必须由 FFprobe 回读；容器、音频流和这类可验证字段不匹配时才拒绝下载。目标格式本来无法表达的字段属于确认后的副本降级，不会因为缺少不可表达的标签取消下载。读取到同一语言的多个源槽位时，MINFO 将其合并为一个可编辑槽位并给出提示。已识别的 `SYLT` 也属于受管理输入：重写歌词时会移除它，当前槽位中的 LRC 原文作为普通歌词写入，而不是生成新的同步帧。源文件始终不受修改。

封面集合有固定类型 `front`、`back`、`disc`、`artist`、`other` 与明确顺序。新增或替换时只接受 PNG、JPG/JPEG、GIF 和 WebP，文件不超过 **2 MB（2,000,000 bytes）**，宽和高均不超过 **1000 px**。该规则只限制用户新选择的封面，不会因为源文件内嵌封面超出限制而删除或修改源封面。若目标容器不能装下全部图片或表达图片类型，用户必须逐项选择保留或省略，不能静默裁剪。

### 固定技术信息

以下信息在输入文件详情中只读：原始文件名、扩展名、探测到的容器和编解码器、文件大小、时长、采样率、声道数、比特率或无损标记。任何无法可靠取得的项目显示“未能读取”，不以推测值填充。

### 导出

- 默认输出为输入文件的原扩展名。
- 首发浏览器导出矩阵只有 MP3、M4A 与 AAC。M4A 的稳定同容器路径包括 AAC 和 ALAC-in-M4A；MP3 ↔ M4A 可转换，ALAC-in-M4A → MP3 属于可见的有损转换。主动选择 AAC 时使用 ADTS 容器并固定输出 `.aac`，不重命名为 `.m4a`。
- 浏览器输出格式控件只展示 `mp3`、`m4a` 与 `aac`，不展示 FLAC、WAV、Ogg、WMA、APE、AMR、MIDI、ALAC、OGA 或手动输入；这些目标只保留在“复制 FFmpeg 命令”的本机路径中。
- ADTS AAC 不承载内嵌封面。选择 AAC 后，表单能力配置须将整个封面集合设为只读/禁用，保留现有封面的可见预览和具体原因；存在待保留或新增封面时，浏览器预检必须列出会从 AAC 副本省略的封面，并在用户确认后继续导出。普通文本标签的实际保留仍须由产物回读验收，不能因扩展名推定成功。
- 浏览器目标格式由独立的音频格式目录维护，表单字段能力与歌词写入/回读能力都由独立配置按格式维护。歌词导入另有按**源格式**维护的读取配置；它不复用导出目标配置，因为输入的容器、可读取别名与输出的可写字段是两个不同的事实。新增格式时，必须新增格式条目、完整字段能力配置、歌词输入读取配置、歌词字段写入/回读配置、预检/回读策略与回归样本；不得通过在 Vue 组件中增加格式名称条件来改变表单逻辑。
- 原格式和新格式都必须经过能力预检。没有可执行浏览器目标、运行时不可用或表单无效时才禁用导出；能够生成文件但会造成字段降级、遗漏、模糊写入或无法逐项验证时，保留用户编辑，列出具体影响，并提供“我已知晓，坚持导出”和“改用 MP3”两个明确选项。
- 导出文件为新下载，不覆盖原始文件。默认名为 `{源文件名} (MINFO).{最终扩展名}`，基础名可编辑但不得含路径分隔符。转码提供高质量、平衡、紧凑三档预设，默认高质量；预设只控制编码质量，不隐式改变采样率或声道数。

## 非目标与边界

- 不承诺任意源格式可以转为任意目标格式。
- 不承诺音频指纹、在线曲库匹配、自动补齐封面或歌词。
- 不把浏览器原生的播放支持误认为文件解析或标签编辑支持。
- 不将 MIDI 视作已编码的波形音频。它是事件序列，不能在没有音源/合成策略的前提下可靠转换为 MP3 等音频文件。
- 不允许静默丢弃封面、歌词或多值标签。目标格式不支持时，用户必须在导出前获知、确认影响后才可生成新副本；源文件始终不受影响。

## 验收标准

首个可发布版本至少满足：

1. 用户可用鼠标、触摸和键盘完成选择、顺序队列、编辑、格式选择、风险确认和导出。
2. 对可支持的样本文件，显示真实的基础标签、封面和时长；读取失败有可理解的原因。
3. 不可编辑字段没有编辑控件，编辑字段都有名称、帮助文本、校验反馈和恢复原值的途径；歌词语言槽位支持键盘新增、编辑和删除，同一语言的重复槽位会被明确拒绝。
4. 输出格式不支持、引擎不可用、内存不足、取消或转换失败时，页面不丢失编辑内容，也不使用模糊的“失败”提示。
5. 每次导出都在客户端完成，且清楚告知用户源文件未上传、未覆盖；确认只对当前文件身份、草稿版本、目标、运行时版本和风险列表有效。

# 架构设计

## 设计读法与约束

设计读法：这是一个面向资深音乐制作人与本地音乐整理者的高信任、高信息密度工作台，采用克制的录音室工具语言，而非营销页或装饰性仪表盘。

交互设计基线：设计变化度 3、动效强度 2、视觉密度 8。动效只用于明确的拖拽、处理进度和结果反馈；表单与技术信息优先可读性、键盘可达性和状态清晰度。该选择采用 `design-taste-frontend` 的可迁移准则，不把其面向营销页面的版式规则硬套到工具型产品。

## 分层与依赖方向

```text
Vue UI
  -> 应用协调层（状态机、命令、视图模型）
    -> 媒体服务端口（检查、读取、编辑、转码、导出）
      -> 能力解析器 / WebCodecs 适配器 / Worker 媒体引擎适配器
        -> 浏览器 API、WebCodecs、FFmpeg WASM
```

依赖只能由上至下。Vue 组件不得直接调用 Worker、FFmpeg 或 WebCodecs；媒体引擎不得依赖任何 Vue 状态。这样可以替换引擎、模拟失败场景，并让 UI 对不同浏览器呈现一致的结果模型。

## 服务层职责

| 服务               | 输入                                | 输出与职责                                                                                                                   |
| ------------------ | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 文件接入服务       | 用户选择的 `File[]`                 | 文件名、扩展名、MIME、大小、基础安全校验与队列项目身份                                                                       |
| 媒体探测服务       | 文件会话                            | 先汇集原生文件/播放技术属性；需要通用容器、轨道、标签、封面或歌词时调用 `ffprobe` WASM，返回规范化结果、警告与非阻塞读取信息 |
| 格式目录服务       | 稳定格式 ID                         | 浏览器可见的格式选项、显示名称、输出扩展名、容器说明与 MIME；不负责宣称媒体内核已支持该格式                                  |
| 表单能力配置服务   | 已解析的目标格式 ID                 | 为每个元数据字段返回可编辑状态和用户可见的禁用原因；每个格式必须有完整配置，不能隐式继承                                     |
| 元数据编辑服务     | 原始快照、表单草稿与表单能力配置    | 字段校验、脏状态、每字段恢复和配置驱动的禁用/只读呈现；组件不得按格式名称分支                                                |
| 歌词文件导入服务   | 单个歌词槽位与用户选择的文本 `File` | 在主线程本地校验扩展名、大小和可解码文本；解析 `.txt`、`.lrc` 与明文 QRC/XML QRC，返回替换候选或稳定的用户错误               |
| 歌词展示解析服务   | 按语言独立的歌词槽位                | 每个槽位的纯文本/带时间标签/混合状态、时间轴行、格式诊断；只生成展示模型，绝不改写原文                                       |
| 媒体运行时缓存服务 | 构建期媒体运行时清单                | 页面启动后后台校验并准备 OPFS 中的 FFmpeg/FFprobe 资产，按版本下载、校验、切换或受控降级                                     |
| 能力服务           | 源文件、目标请求、浏览器能力        | 可用引擎、支持等级、降级原因、数据丢失风险和建议                                                                             |
| 转换服务           | 源文件、规范化目标、编辑后的元数据  | 串行执行、进度、可取消任务、产物或结构化失败原因                                                                             |
| 导出服务           | 产物 Blob 与文件名                  | 浏览器下载、资源释放与完成状态                                                                                               |

所有服务对 UI 返回稳定的领域结果，例如“目标不支持”“目标可转但将丢失封面”“用户取消”“内存资源不足”。禁止把 FFmpeg 日志或 WebCodecs 异常原样作为面向用户的文案。应用协调层维护顺序队列：一个 Worker/内核实例一次只服务一个项目；失败、取消或需要风险确认的项目不阻塞后续项目，且每项草稿独立保存。

读取层须区分会影响结果的警告与已知但不由 MINFO 编辑的私有元数据。当前对 XMP `PRIV` 的识别必须同时满足 owner-identifier 为 `XMP`、完整私有载荷不超过 64 KiB、字节可解码、并通过 XML 解析验证根元素及其命名空间；仅有 owner 字符串时仍保留第三方解析器的未知 owner 警告。通过结构校验的包转换为稳定的非阻塞读取信息，不将 XML 暴露为高级文本标签，也不因它单独增加导出确认。`x:xmptk`、`xmp:CreatorTool` 等包内可写字段不能作为具体软件或厂商的归因证据。浏览器导出仍只承诺它主动管理的字段；通用封装器对该私有帧的保留、重写或省略均不构成逐字保真承诺。

格式目录与表单能力配置分离：前者定义浏览器目标、本机命令专用选项、兜底格式及其稳定标识，后者以浏览器目标标识为键，为标题、歌词、封面等每个现有控件声明是否可编辑。Vue 只根据已解析目标读取能力配置，因此未来增加格式时不会在表单组件中增加格式名称条件。新增格式仍须同时实现和验证导出计划、FFmpeg 参数、产物探测与回读，配置本身不构成媒体内核支持声明。

歌词时间标签的识别和歌词文件导入都是确定性的轻量服务，不依赖媒体 Worker 或 WebCodecs。歌词文件导入只处理用户主动选择的单个本地文本文件，限制为 `.txt`、`.lrc` 与明文 `.qrc`，大小不超过 2 MB；绝不上传、持久化或访问目录。`.txt`/`.lrc` 的可解码原文进入替换候选，明文 QRC/XML QRC 在服务层转换为 LRC 行级时间文本，受保护的加密 QRC 不尝试破解。UI 只消费解析结果和每个语言槽位的展示模型，不能在 Vue 组件中自行用正则分支，更不能为了生成时间轴而排序、去重、删改或规范化用户的歌词原文。语言码的规范化和唯一性检查属于领域层：UI 可以提供可创建的下拉输入，但不能靠组件状态允许两个同语言槽位共存。

## Web Native 能力边界

| 原生能力                       | 可用于 MINFO 的内容                                 | 不能替代的内容                                                   |
| ------------------------------ | --------------------------------------------------- | ---------------------------------------------------------------- |
| `File` / `Blob`                | 文件名、大小、浏览器声明的 MIME、修改时间、原始字节 | 容器解析、嵌入标签、封面、歌词、真实编解码器判断                 |
| `<audio>` / `HTMLMediaElement` | 浏览器能够加载时的只读时长；播放可用性提示          | 通用标题/艺术家/专辑/封面/歌词读取或写入；可靠的所有格式技术属性 |
| Web Audio `AudioBuffer`        | 对浏览器可解码的文件取得时长、采样率、声道数        | 容器标签和封面；对不支持格式的读取；低内存的大文件探测           |
| WebCodecs                      | 逐块编解码与具体编码配置的支持探测                  | 读取/写入音频文件容器、通用嵌入元数据、拆封装、封装              |
| Media Session `MediaMetadata`  | 设置当前网页播放会话在系统媒体控件中的展示信息      | 从用户文件读取标签或把标签写回导出文件                           |
| File System Access             | 把已经生成的 `Blob` 或字节流保存为文件              | 生成或修改音频容器内部的标签结构                                 |

因此，Web Native 是低成本的第一层：始终先读取文件基本属性，并在浏览器支持时补充时长和解码后的技术属性。只要产品需要可靠显示或编辑标题、艺术家、封面、按语言区分的歌词等嵌入元数据，就必须进入非原生的容器解析路径。不能把 `loadedmetadata` 事件、`MediaMetadata` 名称或 WebCodecs 的 `metadata` 参数误解为通用标签 API。

## 引擎选择策略

### 1. 先探测，后承诺

应用启动后和每次选择目标格式时，能力服务都要执行实际探测。WebCodecs 的 `isConfigSupported()` 只说明当前浏览器对某个编解码配置的声明支持，不能代表容器、标签写入或所有设备均可用。能力结果必须带有引擎名称和原因。

### 2. 读取元信息

- 浏览器 `File` API 提供文件名、大小、MIME 和修改时间。
- 隐藏的 `<audio>` 元素在 `loadedmetadata` 后可作为时长的轻量来源；`AudioContext.decodeAudioData()` 在可解码且内存允许时可补充采样率和声道数。两者都只是尽力而为，未知或不可播放时不把它当作失败的唯一依据。
- 浏览器没有通用的原生 API 用于读取或写入 ID3、Vorbis Comment、MP4 atoms、ASF 标签、内嵌封面和歌词。WebCodecs 也只处理编码块，不能直接接收完整音频文件并返回这些字段。
- `SYLT` 是 ID3 的容器级二进制同步歌词帧，不是 Web API 可读写的字段。用 JavaScript 实现它意味着自行维护 ID3v2 帧解析、重组、编码与事件级验证；这不是 Web Native 能力。当前范围明确不生成新的 `SYLT`，也不做其语义或字节级保真验证：LRC 解析仅服务于展示。已识别的原生 `SYLT` 与其他已识别歌词来源由歌词槽位集合接管；导出会清除旧帧，并将当前槽位的原文作为普通歌词写入。预检说明这一同步结构降级，已验证浏览器路径还会回读最终普通歌词槽位，确保表单删除的歌词没有残留。
- 因此完整探测由格式解析适配器完成：可先使用受控浏览器解析器读取常见容器标签，无法覆盖的部分在 Dedicated Worker 中写入临时工作区并调用 `ffprobe` 的 JSON 输出获取 format、stream、tag 和附件信息，再映射为稳定的领域模型。实现阶段不得解析人类可读日志。

### 3. 元数据原格式导出

所谓“原格式”表示保持输出扩展名和可用的源音频流，不是原地修改。浏览器没有将新标签写入 MP3、M4A、ADTS AAC 等容器的标准 API；File System Access 只能保存已经构造好的字节。若编辑了标签、封面或歌词，Worker 中的 `ffmpeg` 负责生成新容器，优先尝试流复制/重封装，只有格式或配置要求时才重编码。写入前检查目标容器的标签能力：不能保留字段时必须阻止无提示导出、逐项显示副本会失去或无法验证的内容，并在用户确认后继续；例如原始 ADTS `.aac` 不承载内嵌封面，确认后会从 AAC 副本省略这些封面。

### 4. 转码导出

优先级按以下顺序决策：

1. 原生能力先确认浏览器能否支持目标编码配置。只有同时具备经过验证的容器拆封装器、封装器和目标标签写入器时，才可使用 WebCodecs 编解码路径。
2. 否则使用 Dedicated Worker 中的 FFmpeg WASM 核心，由 `ffmpeg` 执行重封装或转码。GitHub Pages 基线使用由 pnpm 精确锁定的单线程 `@ffmpeg/core`；具备跨源隔离的本地或其他托管环境可经能力检测选择多线程变体。核心绝不在用户浏览器中从浮动 CDN 拉取；构建只复制锁文件确定的包版本。
3. 两者均不可用或当前 WASM 构建没有目标编码器/复用器时，返回“无法转换”，展示原因和改用 MP3 的建议。

WebCodecs 本身不处理容器拆封装、封装或标签。因此它不是“读写任意音频文件”的完整替代品。`ffprobe` 与 `ffmpeg` 的 WASM 路径可以实现通用探测、标签写入和转码，但实际可支持范围仍由所加载的 WASM 构建中的 demuxer、muxer、decoder、encoder 和目标容器标签规则决定。首版不能在没有端到端样本验证前，把任意格式宣称为完整支持。

## Worker 边界与任务协议

耗时解析、封面解码、转码与大二进制读写全部运行在 Dedicated Worker。主线程仅持有可渲染的缩略图、表单草稿和任务状态。媒体运行时本身可使用其自带 Worker；首版不额外嵌套一个包裹 FFmpeg 的 Worker，以免破坏其加载和取消协议。

Worker 与应用协调层交换五类事件：已开始、阶段进度、预警、成功产物、失败/取消。大 `ArrayBuffer` 在可行时使用 transferable 交接，避免无谓复制；任何对象 URL、封面位图和 Worker 文件系统临时对象都必须在导出、替换文件或离开页面时释放。

取消是协作式的：UI 发出取消请求，服务层停止后续工作、清理临时数据并返回“已取消”。“取消当前任务”继续队列，“停止队列”取消当前并暂停其余项目；两者都不会清除元数据草稿。源文件在等待或恢复后若名称、大小或修改时间变化，必须重新分析并进行三方草稿合并，不能用旧结果继续导出。

### OPFS 媒体运行时缓存

FFmpeg/FFprobe 的 WASM 核心、加载脚本与配套 Worker 文件可能显著增加首次使用成本。页面启动后在后台准备它们，不能等用户点击导出才开始初始化。它们是可再生的同源静态运行时资产，不应和用户音频、封面、歌词或导出产物放在同一持久化目录。媒体运行时缓存服务将它们保存在 OPFS 的独立命名空间中，Worker 从已校验的缓存文件创建临时 Blob URL 供运行时加载；运行时终止后必须撤销这些 URL。

缓存身份由构建生成的 `media-runtime` 清单决定，而不是笼统地由应用版本决定。清单至少包含以下字段：

| 字段             | 用途                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| 清单 schema 版本 | 使缓存布局变化可以安全迁移                                                     |
| 媒体运行时版本   | 标识 `@ffmpeg/ffmpeg`、核心构建与 `ffprobe` 可执行能力的兼容组合               |
| 核心变体         | 区分单线程与多线程核心；GitHub Pages 基线为单线程                              |
| 资产清单         | 每个核心脚本、WASM、附属 Worker 的同源 URL、逻辑名称、MIME、字节长度和 SHA-256 |
| 包分发记录       | 精确 `@ffmpeg/core` / `@ffmpeg/ffmpeg` 包名与版本、核心的已知 FFmpeg 基线      |
| 供应链依据       | 已提交 pnpm 锁文件、Registry 签名审计、漏洞审计、冻结安装和禁用依赖安装脚本    |

启动缓存流程如下：

1. 应用先读取随当前部署发布的小型 `media-runtime` 清单。
2. 检查 OPFS 能力、剩余存储配额和当前缓存清单是否与之完全匹配。
3. 命中时复核资产长度和 SHA-256 后直接使用缓存；不匹配、损坏或缺失时不复用旧二进制。
4. 将新运行时下载到版本化暂存目录，逐个校验完整性，所有资产成功后才写入新清单并切换活动版本。
5. 切换完成后再清理过旧缓存。正常情况下保留当前版本和一个最近的已验证版本；存储不足时只保留当前版本。

源码更新本身不必强制重下相同二进制；当且仅当新的部署清单中的媒体运行时版本、核心变体或资产哈希变化时，缓存更新。这样既满足依赖升级时自动更新，也避免普通 UI 改动重复下载大型 WASM 文件。

OPFS 不可用、用户清理站点存储、配额不足或缓存 Blob URL 无法被当前运行时加载时，应用可以回退到当前 Pages 部署提供的同源、同清单二进制。清单或资产校验失败时，绝不执行未知核心：只允许对同源相同版本重试一次，随后禁用浏览器媒体引擎，同时保留草稿与复制本机脚本的恢复路径。

运行时核心来自 pnpm 精确锁定的 `@ffmpeg/core`，`@ffmpeg/ffmpeg` 是对应的固定 Worker/API 包装接口。MINFO 不把该 core 误称为“最新官方 FFmpeg”，而是在界面和清单中展示其实际基线。MINFO 是个人自托管项目，不根据 LGPL、GPL 或 nonfree 标签拒绝核心；若清单带有许可证信息，只用于追溯。完整策略见 [07-media-runtime-supply-chain.md](07-media-runtime-supply-chain.md)。

### 活动任务的临时 OPFS 工作区

用户媒体不得进入持久缓存，但活动分析或导出可在独立的临时 OPFS 工作区使用字节，以缓解大文件内存压力。工作区只在任务开始时创建，完成、失败或取消时删除；应用启动时清理遗留工作区。队列恢复只保存用户意图和在浏览器允许时的文件句柄，不保存音频、封面、歌词或产物字节。

## 关键技术事实

- [HTMLMediaElement `duration`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/duration) 与 [AudioBuffer](https://developer.mozilla.org/en-US/docs/Web/API/AudioBuffer) 说明浏览器可读取的部分技术属性。
- [Media Session `metadata`](https://developer.mozilla.org/en-US/docs/Web/API/MediaSession/metadata) 是网页向系统媒体控件提供展示信息的 API，而不是文件标签读取器。
- [WebCodecs 概览](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API) 明确其不提供文件容器的内建拆封装与封装能力；[规范](https://www.w3.org/TR/webcodecs/) 也指出编码媒体不是容器化数据。
- [FFmpeg WASM API](https://ffmpegwasm.netlify.app/docs/api/ffmpeg/classes/ffmpeg/) 提供 `ffprobe()`；[FFprobe 官方文档](https://ffmpeg.org/ffprobe.html) 说明它可输出容器、流和标签信息；[FFmpeg 官方文档](https://ffmpeg.org/ffmpeg.html) 说明 `-metadata` 可在输出文件设置键值元数据。
- [OPFS 文档](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) 说明它按源站私有、受存储配额限制、可在 Worker 中高效访问，且站点数据被清理时会删除缓存。

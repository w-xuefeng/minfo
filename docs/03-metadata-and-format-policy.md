# 元数据与格式策略

## 规范化原则

界面使用一个与格式无关的“编辑草稿”，而不是直接把任一文件格式的字段名暴露给用户。读取时，适配器将源标签映射到草稿；导出时，适配器按照目标容器映射回可支持的原生标签。

草稿字段包含值、原始值、读取状态、验证状态和写入可行性。空字符串、未读取、源文件中不存在、目标格式无法表示是四种不同状态，必须分别展示和处理。

读取优先级是浏览器原生文件/播放技术属性，随后才是 Worker 中 `ffprobe` 的容器级探测。标题、艺术家、专辑、封面、歌词和格式特定技术属性以 `ffprobe` 的结构化结果为权威来源；原生属性只能作为快速补充和交叉校验，不能覆盖已探测到的真实容器信息。

## 字段处理规则

| 字段类型 | UI 编辑方式 | 导出策略 |
| --- | --- | --- |
| 单值文本 | 单行输入 | 写入目标格式等价字段；不支持则列入阻止或警告 |
| 多值流派/艺术家 | 可增删的标签输入，导出前保留顺序 | 依据目标格式的分隔规则转换，不能无损表达时提示 |
| 年份 | 年份输入，而非任意日期控件 | 接受四位年份；复杂日期超出首版 |
| 曲目/碟号 | 数字和总数成对输入 | 不允许负数或零；缺失总数可以只写编号 |
| 封面 | 图片选择、替换、移除、预览 | 新增/替换仅接受 PNG、JPG/JPEG、GIF、WebP，最大 2 MB（2,000,000 bytes）、1000×1000 px；导出前还需检测容器支持 |
| 歌词原文 | 多行文本，自动识别 LRC 式时间标签 | 按原文写入目标可表达的歌词字段；LRC 检测只影响展示，不自动转换为同步歌词编码 |
| 评论 | 多行文本 | 需保留编码与语言差异的诊断；首版只编辑一个默认评论槽位 |

### 封面替换校验

封面校验仅发生在用户新增或替换封面时，不回溯拒绝源文件已内嵌的封面。允许的实际媒体类型为 `image/png`、`image/jpeg`、`image/gif` 与 `image/webp`，对应常见扩展名为 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`。

| 规则 | 首版限制 | 失败处理 |
| --- | --- | --- |
| 文件格式 | PNG、JPG/JPEG、GIF、WebP | 保留当前有效封面和表单草稿，提示用户选择允许的格式 |
| 文件大小 | 不超过 2 MB（2,000,000 bytes） | 显示当前大小和上限，不读取为封面预览 |
| 图像宽高 | 宽和高均不超过 1000 px | 显示实际尺寸和允许范围 |

校验顺序为：大小与声明类型的快速检查、文件签名检查、图像头尺寸检查、受控解码预览。扩展名和浏览器声明的 MIME 只是提示，不足以作为通过依据。GIF 和 WebP 被作为允许的图片格式处理；若目标容器或标签写入器不能保留该封面，则在导出预检中按普通“封面无法保留”风险提示，不自动转换或静默移除。

### 歌词时间标签检测与写入

歌词原文是唯一的可编辑和导出来源。解析服务在导入歌词、粘贴歌词、输入停止后和恢复原值后重新检测，不会删除标签、合并行、重排时间或替换换行符。

| 展示状态 | 识别条件 | 展示规则 |
| --- | --- | --- |
| 带时间标签 | 至少一行以一个或多个有效 LRC 时间标签开头 | 生成时间轴行，时间与歌词内容分列展示 |
| 混合 | 存在有效时间标签，且还有非空行没有时间标签 | 时间轴保留带标签的行，未带标签行作为上下文显示，并提示“部分行没有时间标签” |
| 纯文本 | 不存在有效时间标签 | 按原始换行分段和换行显示，不将全部内容压成一行 |

首版识别的行级时间标签为 `[mm:ss]`、`[mm:ss.xx]`、`[mm:ss.xxx]`，其中秒数为 `00-59`，分钟数可大于 59；同一行的多个时间标签生成多个时间轴行。`[ar:…]`、`[ti:…]`、`[al:…]`、`[offset:…]` 等 LRC 元标签不视为时间标签，仍按原文保留。格式不完整或非法的方括号文本也保留为原文，不因解析失败丢失内容。

检测到 LRC 不等于目标音频格式支持同步歌词。首版将原文写入目标格式可表达的歌词字段，但不承诺把 LRC 转换为 SYLT 或其他播放器专用同步歌词结构。若目标格式无法保留歌词，导出预检仍按字段级风险阻止或要求用户确认。

## 内置格式选项的语义

下表是 UI 的候选项字典，不是跨浏览器的无条件能力承诺。每项在导出前必须由能力服务结合源文件、目标配置和当前引擎实际确认。

| 用户输入 | 规范化目标 | 说明与首版策略 |
| --- | --- | --- |
| `mp3` | MP3 容器与 MP3 音频 | 推荐的通用兜底选项。常见标签为 ID3，仍以实际引擎能力为准。 |
| `aac` | 原始 AAC 比特流 | 不是 M4A。标签与封面承载能力弱，若用户编辑富元数据，应优先建议 `m4a`。 |
| `flac` | FLAC | 可承载 Vorbis Comment 和图片块；实际编码需能力探测。 |
| `m4a` | MP4 音频容器 | 默认编码策略为 AAC；也可能承载 ALAC，必须在预检中明确。 |
| `wma` | ASF/WMA | 浏览器和 WASM 编码器可能不可用，不能预设成功。 |
| `wav` | RIFF/WAVE | 通常用于 PCM；标签兼容性不如专为音乐标签设计的容器，需预警。 |
| `ogg` | Ogg 容器 | 应在预检中说明使用 Vorbis 或 Opus，不能只显示模糊的“OGG”。 |
| `ape` | Monkey's Audio | 通常只应视为条件性候选，不能把读取支持推断为编码支持。 |
| `amr` | AMR | 受编码器和授权构建影响，条件性候选。 |
| `mid` / `midi` | MIDI 事件文件 | 不作为波形音频转码目标；需要音源和渲染策略，首版应给出不支持原因。 |
| `alac` | ALAC 编解码器 | 规范化为 M4A 容器中的 ALAC，而不是承诺 `.alac` 独立文件。 |
| `oga` | Ogg audio 容器 | 与 `ogg` 共享容器规则，但保持用户选择的扩展名。 |

手动输入会先清理空格、前导点和大小写，再查候选字典或交给能力服务。如果输入是未知扩展名，应显示“需要验证的自定义格式”，而非直接开始转换。

## 支持等级

能力服务以以下等级返回结果：

| 等级 | 含义 | UI 行为 |
| --- | --- | --- |
| 完整支持 | 可读取或导出，当前编辑字段可保留 | 正常导出 |
| 支持但有损 | 音频可导出，但明确字段无法保留或会被降级 | 显示字段清单，用户确认后继续 |
| 仅可读取 | 可查看输入，但无可用写入/转换路径 | 禁用导出并解释 |
| 未支持 | 引擎、容器、编码器或输入内容不支持 | 说明原因，提供改用 MP3 的操作 |
| 未知 | 尚未完成检测或检测无法判定 | 保持导出按钮不可用，允许重试或保留草稿 |

## 不可逆风险处理

- 从无损转有损、降低采样率或更改声道属于音频内容变换，必须在导出预检中说明。
- 当目标不能承载封面、歌词、评论或多值字段时，列出每一个受影响字段，而不是笼统称为“部分元数据丢失”。
- 原格式导出也可能因不完整源标签、非法标签或容器限制产生差异。预检无法保证时显示“可能变化”的原因。
- 输出文件名默认使用源文件基名加 `-minfo` 和目标扩展名，避免让用户误以为下载会覆盖源文件。

## 为什么不能只依赖扩展名与浏览器播放

扩展名可能被改名，MIME 可能为空，而同一容器可以承载多种编解码器。`HTMLMediaElement.duration` 能在媒体元数据加载后给出只读时长，但它不提供通用标签读写能力。详见 [MDN 的 duration 文档](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/duration) 与 [WebCodecs 编解码器注册表](https://www.w3.org/TR/webcodecs-codec-registry/)。

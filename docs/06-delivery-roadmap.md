# 实施路线与验证计划

## 实施顺序

### 阶段 A：脚手架与质量基线

创建 Vite + Vue 3 + TypeScript + pnpm 项目，配置严格 TypeScript、格式化、lint、单元测试和 GitHub Pages 构建。配置 `main` push 触发的发布工作流：构建通过后将 `dist/` 覆盖式发布到孤儿 `pages` 分支，GitHub Pages 从该分支根目录提供站点。构建流程还应生成媒体运行时清单与每个 FFmpeg/FFprobe WASM 资产的 SHA-256。此阶段不接入媒体内核，先验证项目站点的 `base` 路径、静态资源和发布工作流。

完成条件：空应用可在项目型 GitHub Pages URL 下刷新和加载资源；`main` 中的源码和 `docs/` 不会进入 `pages`；CI 通过类型检查、lint、测试、构建和发布。

### 阶段 B：领域模型与 UI 状态机

实现文件会话、元数据草稿、字段状态、导出目标、能力结果和任务状态机。使用假媒体服务锁定 UI 的空、拖拽、解析、成功、字段错误、格式不支持、转换中、取消、成功和失败状态。

完成条件：无媒体依赖时，所有交互状态可测试，替换文件和取消不会丢失未确认前应保留的草稿。

### 阶段 C：轻量探测与原格式元数据路径

接入 File API、原生时长/AudioBuffer 技术属性读取和能力探测；明确其不能读取通用嵌入标签。实现 OPFS 媒体运行时缓存服务，覆盖缓存命中、版本升级、校验失败、配额不足与同源网络回退。随后接入 Worker 中的 `ffprobe` JSON 探测，优先完成 MP3、M4A、FLAC、WAV、Ogg 样本的读取。再实现 `ffmpeg` 驱动的可验证元数据写入/重封装路径，并记录每种格式的字段保留行为。

完成条件：支持样本经过编辑、导出、重新导入后，字段结果符合格式策略表；不支持的字段被预检拦截或明确确认。

### 阶段 D：能力路由与转码

实现 WebCodecs 可用性探测、容器适配前置条件和 Worker FFmpeg WASM 单线程后备。先完成 MP3 与 M4A 的端到端路线，再以样本验证增加 FLAC、WAV、Ogg 等。WMA、APE、AMR、MIDI/ALAC 不因出现在下拉列表就默认宣布完成。

完成条件：每个宣称支持的“源格式 -> 目标格式”都有自动化或人工可复现的样本结果、元数据保留记录和失败降级路径。

### 阶段 E：性能、无障碍与发布

加入大文件资源提示、取消清理、键盘流、屏幕阅读器播报、明暗模式和浏览器矩阵。最后配置 GitHub Pages Actions 部署和隐私说明。

完成条件：达到本文件的测试门槛，无已知阻塞错误后发布。

## 发布门槛

1. 只将通过端到端样本验证的格式标为“完整支持”。
2. 类型检查、lint、单元测试、构建和格式回归全部通过。
3. 所有失败路径均具有用户可理解的说明、恢复操作和草稿保留行为。
4. 不存在源文件上传、隐式网络媒体请求或将私人标签写入遥测的路径。
5. 项目站点在 GitHub Pages 仓库子路径下正常工作，且其发布源为由 Actions 管理的孤儿 `pages` 分支。

## 当前开放决策

- 选择用于容器拆封装、封装和结构化标签结果的具体适配器前，必须对许可证、包体积、浏览器支持和测试样本进行评估；不在此阶段引入依赖。
- 需要用真实样本确认 FFmpeg WASM 构建中可用的编码器，再决定 WMA、APE、AMR、ALAC 的可见支持等级。
- 音频文件的资源告警阈值和单文件处理上限必须由性能测试决定；封面替换的首版保护阈值已固定为 PNG、JPG/JPEG、GIF、WebP，最大 2 MB（2,000,000 bytes）和 1000×1000 px。
- 若用户需要将 LRC 转换为高保真 SYLT、逐词同步歌词或播放器专用同步歌词结构，应单独设计元数据映射和兼容性策略；当前需求仅承诺原文保留与视觉时间轴预览。

# MINFO

**MINFO**，即 **Music Information**，是一款部署在 GitHub Pages 的浏览器端音频元信息管理工具。

它帮助用户查看和编辑本地音频文件的标题、艺术家、专辑、封面、歌词等信息，并导出保持原格式或转换后的新文件。文件默认只在用户自己的浏览器中处理，源文件不会被修改。

> 当前仓库正在实施首版。文档描述的是已确认的产品契约；未完成的媒体运行时能力会在界面中明确显示为不可用，而不会被提前承诺。

## 当前实现状态

- 已可运行：Vite/Vue 工作台、顺序队列、音频标签读取、标准字段/原始标签冲突处理、LRC/纯文本歌词预览、封面签名与尺寸校验、本机 FFmpeg 脚本、导出预检、OPFS 运行时缓存代码，以及 Pages 发布/回滚工作流。
- 已实现但等待真实运行时验证：浏览器 FFmpeg/FFprobe 服务会始终核对输出容器和音频流；对已改标签、封面和高级标签尽可能回读。用户确认的字段降级或输入未完整探测会按预检说明交付新副本，输出容器或音频流未通过验证时才不会下载文件。
- 已随仓库交付：由 pnpm 锁定的 `@ffmpeg/ffmpeg@0.12.15` 和 `@ffmpeg/core@0.12.10` 单线程 WASM 核心。构建会将核心复制为同源静态资产，浏览器在加载和 OPFS 缓存复用前校验 SHA-256；`ffprobe()` 使用同一核心。
- 尚待实现：活动任务的临时 OPFS 用户媒体工作区。当前用户媒体只进入内存和 FFmpeg Worker 的临时文件系统，不会被持久化到 OPFS。

## 计划中的体验

1. 选择或拖入一个或多个音频文件，按顺序逐项处理。
2. 查看可编辑标签和只读技术信息，例如扩展名、大小、时长、编解码器、采样率和声道数。
3. 在元数据表单之前选择导出目标。默认保持原格式；首发浏览器导出矩阵只提供 MP3、M4A 与 AAC。选择 AAC 时固定输出原始 ADTS `.aac`，不会改名为 `.m4a`；其他格式不出现在浏览器输出格式控件中。
4. 再编辑标题、艺术家、专辑、流派、曲目、封面和歌词等字段。表单会按已选目标的能力配置决定哪些字段可编辑；例如 ADTS AAC 不承载内嵌封面，选择 AAC 后封面组保留可见但不可编辑，并给出原因。歌词按语言槽位分别管理，可单独新增、编辑或删除；语言输入提供 `und`、`zho`、`eng`、`jpn` 的可选项，也允许创建其他规范语言码，同一语言只能有一个槽位。每个槽位会自动识别 LRC 式时间标签；默认折叠的预览在展开后按时间轴或保留换行的纯文本展示。新增或替换封面仅接受 PNG、JPG/JPEG、GIF、WebP，最大 2 MB、1000×1000 px。
5. 在导出前获得真实的兼容性检查。若浏览器可以生成新文件但目标会丢失、无法精确保留或无法验证某些字段，界面会逐项说明影响；勾选“我已知晓，坚持导出”后仍可导出副本。只有没有可执行的浏览器目标、运行时不可用或表单本身无效时才禁用导出，并建议 MP3 或本机 FFmpeg 作为兜底。
6. 生成名为 `{源文件名} (MINFO).{扩展名}` 的新下载文件，原文件保持不变；也可复制同一导出计划对应的本机 FFmpeg 脚本。

## 技术方向

- UI：Vite、Vue 3、TypeScript、pnpm。
- 架构：UI 层与媒体服务层严格分离；UI 不直接依赖媒体内核。
- 媒体能力：当前先使用 File/HTMLAudio 等 Web Native 能力取得文件属性和尽力而为的时长，通用标签读取使用浏览器解析器和受控媒体运行时；写入或转码由 Worker 中的 FFmpeg 路径兜底。WebCodecs 能力探测属于后续增强，且不会被误当作容器或标签 API。
- 运行时：页面启动后在后台准备由 pnpm 精确锁定的同源媒体运行时，并优先复用 OPFS 缓存。构建、浏览器加载与 Pages 产物均校验资产 SHA-256；pnpm 对所有直接和传递依赖执行冻结锁文件、Registry 签名与漏洞审计。许可证字段只用于追溯，不作为加载或发布白名单。详见[运行时供应链策略](docs/07-media-runtime-supply-chain.md)。
- 部署：`main` 保存源码与文档。每次 push `main` 由 GitHub Actions 验证并构建；`pages` 首次创建为孤儿分支，之后保留每次成功构建的提交历史，供手动回滚。
- 隐私：不设后端转码和文件上传。当前用户媒体只在活动任务的内存和 Worker 临时文件系统中存在，不作持久保存；临时 OPFS 工作区是下一阶段的内存优化。

WebCodecs 是低层编解码 API，不包含通用的文件容器拆封装、封装或标签读写；浏览器原生可读取文件属性、可用时长及部分解码后的技术信息，但无法通用地读写 ID3、MP4、Vorbis、ASF 等标签。因此 MINFO 会基于运行时能力选择路径：原生能力优先，`ffprobe` WASM 负责完整探测，`ffmpeg` WASM 负责生成带新元信息的文件或转码，绝不会把扩展名或浏览器播放能力误当成格式支持承诺。

## 开发媒体日志

当 FFprobe 输入预检未产生可验证的 JSON 时，界面会展示检查阶段、退出码和有限的错误行，并把“输入未完整交叉检查”列为导出副本风险；用户确认后仍可尝试生成副本。当前 WASM 核心可能在已写出有效 JSON 时返回已知的 `-1` 哨兵值；MINFO 仅在 JSON 同时证明容器和音频流时将其视为已验证，绝不因该兼容处理接受空、损坏或不完整的探测结果。输出文件仍必须通过容器和音频流完整性检查才会下载。若需要在浏览器开发者工具的 **Debug/Verbose** 分类中查看完整的 FFmpeg 与 FFprobe 输出，可仅在本地开发时运行：

```bash
VITE_MINFO_MEDIA_DEBUG=1 pnpm dev
```

也可在未提交的 `.env.development.local` 中写入 `VITE_MINFO_MEDIA_DEBUG=1`。该开关还要求 Vite 的 `DEV` 模式，因此生产构建和 GitHub Pages 即使带有同名变量也不会写入控制台。

## 当前首发边界

- 可编辑的标准字段包括多值艺术家、专辑艺术家和流派、日期（`YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`）、曲目/碟片、作曲者、评论、多个带类型和顺序的封面，以及按语言唯一的歌词槽位。
- 新增或替换封面仅接受 PNG、JPG/JPEG、GIF、WebP，最大 2 MB（2,000,000 bytes），宽高均不超过 1000 px；源文件中已存在的超限封面不会被自动删除。
- 每个歌词槽位都保留自己的原始 LRC 或纯文本。首个槽位以普通 `lyrics` / `lyrics_language` 标签写入，其余槽位尝试写入带语言后缀的普通歌词标签（如 `lyrics-eng`）；后者是跨容器的尽力而为映射，预检会要求确认其兼容性风险。浏览器不生成 `SYLT`，也不对 `SYLT` 做事件或字节级回读验收。检测到源 `SYLT` 时会说明同步歌词可能保留、丢失或与普通歌词不一致；用户确认后仍可导出新副本，源文件不受影响。
- MP3 与 M4A 的同容器编辑、MP3 ↔ M4A 转换，以及 MP3/M4A → AAC（ADTS `.aac`）是首发目标。ALAC-in-M4A 可作为稳定读取和转 MP3/AAC 输入；原始 AAC 不承载内嵌封面，因此存在任一要保留或新增封面时会明确说明这些封面不会写入 AAC 副本，并在确认后继续导出。
- 浏览器输出选项由音频格式目录维护；各目标格式的字段可编辑性由独立的表单能力配置维护。新增格式时必须同时补充两份配置和对应的媒体回归测试，Vue 表单不应新增格式名称分支。
- 实际可支持范围以运行时预检和回读验收为准。失败、取消、格式不支持或资源不足时，草稿保留，并可改用 MP3 或复制本机脚本继续。
- 原始文本标签的同名重复槽位（例如带描述符的多条扩展标签）无法由通用写入器精确定位；界面会说明相关槽位可能被合并、重排或无法逐项验证，用户确认后以尽力而为方式生成副本，绝不修改源文件。

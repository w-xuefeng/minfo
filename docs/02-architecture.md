# 架构设计

## 设计读法与约束

设计读法：这是一个面向本地音乐整理者的高信任、信息密度中等的单文件工具界面，采用克制的编辑器式语言，而非营销页或仪表盘式装饰。

交互设计基线：设计变化度 3、动效强度 2、视觉密度 6。动效只用于明确的拖拽、处理进度和结果反馈；表单与技术信息优先可读性、键盘可达性和状态清晰度。该选择采用 `design-taste-frontend` 的可迁移准则，不把其面向营销页面的版式规则硬套到工具型产品。

## 分层与依赖方向

```text
Vue UI
  -> 应用协调层（状态机、命令、视图模型）
    -> 媒体服务端口（检查、读取、编辑、转码、导出）
      -> 能力解析器 / WebCodecs 适配器 / Worker 媒体引擎适配器
        -> 浏览器 API、WebCodecs、FFmpeg WASM
```

依赖只能由上至下。Vue 组件不得直接调用 Worker、FFmpeg 或 WebCodecs；媒体引擎不得依赖任何 Vue 状态。这样可以替换引擎、模拟失败场景，并让 UI 对不同浏览器呈现一致的结果模型。

## 服务层职责

| 服务 | 输入 | 输出与职责 |
| --- | --- | --- |
| 文件接入服务 | 用户选择的 `File` | 文件名、扩展名、MIME、大小、基础安全校验与一次性会话标识 |
| 媒体探测服务 | 文件会话 | 先汇集原生文件/播放技术属性；需要通用容器、轨道、标签、封面或歌词时调用 `ffprobe` WASM，返回规范化结果与诊断信息 |
| 元数据编辑服务 | 原始快照与表单草稿 | 字段校验、脏状态、每字段恢复、目标格式可表达性检查 |
| 歌词展示解析服务 | 歌词原文 | 纯文本/带时间标签/混合状态、时间轴行、格式诊断；只生成展示模型，绝不改写原文 |
| 媒体运行时缓存服务 | 构建期媒体运行时清单 | 校验 OPFS 中的 FFmpeg/FFprobe 资产，按版本下载、校验、切换或回退到同源网络加载 |
| 能力服务 | 源文件、目标请求、浏览器能力 | 可用引擎、支持等级、降级原因、数据丢失风险和建议 |
| 转换服务 | 源文件、规范化目标、编辑后的元数据 | 进度、可取消任务、产物或结构化失败原因 |
| 导出服务 | 产物 Blob 与文件名 | 浏览器下载、资源释放与完成状态 |

所有服务对 UI 返回稳定的领域结果，例如“目标不支持”“目标可转但将丢失封面”“用户取消”“内存资源不足”。禁止把 FFmpeg 日志或 WebCodecs 异常原样作为面向用户的文案。

歌词时间标签的识别是确定性的轻量服务，不依赖媒体 Worker 或 WebCodecs。UI 只消费其展示模型，不能在 Vue 组件中自行用正则分支，更不能为了生成时间轴而排序、去重、删改或规范化用户的歌词原文。

## Web Native 能力边界

| 原生能力 | 可用于 MINFO 的内容 | 不能替代的内容 |
| --- | --- | --- |
| `File` / `Blob` | 文件名、大小、浏览器声明的 MIME、修改时间、原始字节 | 容器解析、嵌入标签、封面、歌词、真实编解码器判断 |
| `<audio>` / `HTMLMediaElement` | 浏览器能够加载时的只读时长；播放可用性提示 | 通用标题/艺术家/专辑/封面/歌词读取或写入；可靠的所有格式技术属性 |
| Web Audio `AudioBuffer` | 对浏览器可解码的文件取得时长、采样率、声道数 | 容器标签和封面；对不支持格式的读取；低内存的大文件探测 |
| WebCodecs | 逐块编解码与具体编码配置的支持探测 | 读取/写入音频文件容器、通用嵌入元数据、拆封装、封装 |
| Media Session `MediaMetadata` | 设置当前网页播放会话在系统媒体控件中的展示信息 | 从用户文件读取标签或把标签写回导出文件 |
| File System Access | 把已经生成的 `Blob` 或字节流保存为文件 | 生成或修改音频容器内部的标签结构 |

因此，Web Native 是低成本的第一层：始终先读取文件基本属性，并在浏览器支持时补充时长和解码后的技术属性。只要产品需要可靠显示或编辑标题、艺术家、封面、歌词等嵌入元数据，就必须进入非原生的容器解析路径。不能把 `loadedmetadata` 事件、`MediaMetadata` 名称或 WebCodecs 的 `metadata` 参数误解为通用标签 API。

## 引擎选择策略

### 1. 先探测，后承诺

应用启动后和每次选择目标格式时，能力服务都要执行实际探测。WebCodecs 的 `isConfigSupported()` 只说明当前浏览器对某个编解码配置的声明支持，不能代表容器、标签写入或所有设备均可用。能力结果必须带有引擎名称和原因。

### 2. 读取元信息

- 浏览器 `File` API 提供文件名、大小、MIME 和修改时间。
- 隐藏的 `<audio>` 元素在 `loadedmetadata` 后可作为时长的轻量来源；`AudioContext.decodeAudioData()` 在可解码且内存允许时可补充采样率和声道数。两者都只是尽力而为，未知或不可播放时不把它当作失败的唯一依据。
- 浏览器没有通用的原生 API 用于读取或写入 ID3、Vorbis Comment、MP4 atoms、ASF 标签、内嵌封面和歌词。WebCodecs 也只处理编码块，不能直接接收完整音频文件并返回这些字段。
- 因此完整探测由格式解析适配器完成：在 Dedicated Worker 中将文件写入 WASM 临时文件系统，调用 `ffprobe` 的 JSON 输出获取 format、stream、tag 和附件信息，再映射为稳定的领域模型。实现阶段不得解析人类可读日志。

### 3. 元数据原格式导出

所谓“原格式”表示保持输出扩展名和可用的源音频流，不是原地修改。浏览器没有将新标签写入 MP3、M4A、FLAC 等容器的标准 API；File System Access 只能保存已经构造好的字节。若编辑了标签、封面或歌词，Worker 中的 `ffmpeg` 负责生成新容器，优先尝试流复制/重封装，只有格式或配置要求时才重编码。写入前检查目标容器的标签能力，并在不能保留字段时阻止无提示导出。

### 4. 转码导出

优先级按以下顺序决策：

1. 原生能力先确认浏览器能否支持目标编码配置。只有同时具备经过验证的容器拆封装器、封装器和目标标签写入器时，才可使用 WebCodecs 编解码路径。
2. 否则使用 Dedicated Worker 中的 FFmpeg WASM 单线程核心，由 `ffmpeg` 执行重封装或转码。
3. 两者均不可用或当前 WASM 构建没有目标编码器/复用器时，返回“无法转换”，展示原因和改用 MP3 的建议。

WebCodecs 本身不处理容器拆封装、封装或标签。因此它不是“读写任意音频文件”的完整替代品。`ffprobe` 与 `ffmpeg` 的 WASM 路径可以实现通用探测、标签写入和转码，但实际可支持范围仍由所加载的 WASM 构建中的 demuxer、muxer、decoder、encoder 和目标容器标签规则决定。首版不能在没有端到端样本验证前，把任意格式宣称为完整支持。

## Worker 边界与任务协议

耗时解析、封面解码、转码与大二进制读写全部运行在 Dedicated Worker。主线程仅持有可渲染的缩略图、表单草稿和任务状态。

Worker 与应用协调层交换五类事件：已开始、阶段进度、预警、成功产物、失败/取消。大 `ArrayBuffer` 在可行时使用 transferable 交接，避免无谓复制；任何对象 URL、封面位图和 Worker 文件系统临时对象都必须在导出、替换文件或离开页面时释放。

取消是协作式的：UI 发出取消请求，服务层停止后续工作、清理临时数据并返回“已取消”。取消不会清除元数据草稿。

### OPFS 媒体运行时缓存

FFmpeg/FFprobe 的 WASM 核心、加载脚本与配套 Worker 文件可能显著增加首次使用成本。它们是可再生的同源静态运行时资产，不应和用户音频、封面、歌词或导出产物放在同一持久化目录。媒体运行时缓存服务将它们保存在 OPFS 的独立命名空间中，Worker 从已校验的缓存文件创建临时 Blob URL 供运行时加载；运行时终止后必须撤销这些 URL。

缓存身份由构建生成的 `media-runtime` 清单决定，而不是笼统地由应用版本决定。清单至少包含以下字段：

| 字段 | 用途 |
| --- | --- |
| 清单 schema 版本 | 使缓存布局变化可以安全迁移 |
| 媒体运行时版本 | 标识 `@ffmpeg/ffmpeg`、核心构建与 `ffprobe` 可执行能力的兼容组合 |
| 核心变体 | 区分单线程与多线程核心；GitHub Pages 基线为单线程 |
| 资产清单 | 每个核心脚本、WASM、附属 Worker 的同源 URL、逻辑名称、MIME、字节长度和 SHA-256 |
| 构建标识 | 关联本次部署的媒体运行时构建，而不把任意源代码小改动误当作二进制更新 |

启动缓存流程如下：

1. 应用先读取随当前部署发布的小型 `media-runtime` 清单。
2. 检查 OPFS 能力、剩余存储配额和当前缓存清单是否与之完全匹配。
3. 命中时复核资产长度和 SHA-256 后直接使用缓存；不匹配、损坏或缺失时不复用旧二进制。
4. 将新运行时下载到版本化暂存目录，逐个校验完整性，所有资产成功后才写入新清单并切换活动版本。
5. 切换完成后再清理过旧缓存。正常情况下保留当前版本和一个最近的已验证版本；存储不足时只保留当前版本。

源码更新本身不必强制重下相同二进制；当且仅当新的部署清单中的媒体运行时版本、核心变体或资产哈希变化时，缓存更新。这样既满足依赖升级时自动更新，也避免普通 UI 改动重复下载大型 WASM 文件。

OPFS 不可用、用户清理站点存储、配额不足、校验失败或缓存 Blob URL 无法被当前运行时加载时，应用必须回退到当前 Pages 部署提供的同源二进制。缓存失败只影响首次加载性能，不能阻止探测、导出或转码功能。

## 关键技术事实

- [HTMLMediaElement `duration`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/duration) 与 [AudioBuffer](https://developer.mozilla.org/en-US/docs/Web/API/AudioBuffer) 说明浏览器可读取的部分技术属性。
- [Media Session `metadata`](https://developer.mozilla.org/en-US/docs/Web/API/MediaSession/metadata) 是网页向系统媒体控件提供展示信息的 API，而不是文件标签读取器。
- [WebCodecs 概览](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API) 明确其不提供文件容器的内建拆封装与封装能力；[规范](https://www.w3.org/TR/webcodecs/) 也指出编码媒体不是容器化数据。
- [FFmpeg WASM API](https://ffmpegwasm.netlify.app/docs/api/ffmpeg/classes/ffmpeg/) 提供 `ffprobe()`；[FFprobe 官方文档](https://ffmpeg.org/ffprobe.html) 说明它可输出容器、流和标签信息；[FFmpeg 官方文档](https://ffmpeg.org/ffmpeg.html) 说明 `-metadata` 可在输出文件设置键值元数据。
- [OPFS 文档](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) 说明它按源站私有、受存储配额限制、可在 Worker 中高效访问，且站点数据被清理时会删除缓存。

# UI 与交互规范

## 页面结构

单页面由六个有明确顺序的区域构成：

1. 文件接入区：选择一个或多个文件和拖拽入口。
2. 顺序队列区：项目状态、当前项目、取消当前任务与停止队列操作。
3. 文件概览区：当前项目的文件身份、封面预览、解析状态和固定技术属性。
4. 导出目标区：置于所有可编辑元数据之前，包含格式、输出文件名和需要转码时的质量预设，并即时说明该目标会限制哪些编辑表单。
5. 可编辑元数据区：按“基本信息、编排信息、富内容”分组的表单，字段状态由已选目标的表单能力配置决定。
6. 导出确认区：兼容性预检、风险确认、复制本机脚本与唯一的主操作“导出”。

桌面宽度使用两列：概览作为稳定侧栏，导出目标、表单和导出确认作为主列；小于 768px 时折叠为单列，导出目标仍位于元数据之前，导出确认位于表单之后。每个输入标签置于输入框上方，错误文字置于输入框下方，绝不以 placeholder 代替标签。

## 视觉语言

- 主题默认跟随系统明暗模式，使用一套语义色彩 token。主强调色只有一种，用于主按钮、焦点和真实的处理中状态。
- 表面层级通过留白、细分组和有限的边界表达，不将每个字段包进卡片。
- 使用一种统一圆角规则：输入和面板为柔和圆角，按钮可为胶囊形，但规则须全局一致。
- 不使用与信息无关的炫光、渐变网格、自动循环动画、装饰状态点或营销式假数据。
- 动效只反馈操作：拖拽激活、面板展开、任务进度和成功下载。所有非必要动画应遵守 `prefers-reduced-motion`。

## 文件接入状态

| 状态     | 呈现与行为                                                                       |
| -------- | -------------------------------------------------------------------------------- |
| 空状态   | 明确的拖放区域、可聚焦的“选择音频文件”按钮、支持范围说明和隐私提示。             |
| 拖拽悬停 | 仅在真实可接受文件拖入时显示高对比边框与文字变化；不以颜色作为唯一信号。         |
| 校验中   | 显示文件名、大小和可取消的准备状态，阻止重复提交。                               |
| 解析中   | 骨架轮廓对应最终概览与表单结构，并显示当前阶段，例如“读取标签”或“检查导出能力”。 |
| 解析成功 | 展示已读信息；未能读取的字段逐项标注，不填空白假装没有内容。                     |
| 解析失败 | 保留文件名和诊断摘要，提供“重新选择文件”和“查看技术详情”两个明确动作。           |

一次加入多个文件后，队列只运行一个媒体任务。失败、需要确认或被取消的项目显示明确状态并不阻塞后续项目；每项草稿独立保留。当前任务支持“取消当前任务”，队列还支持“停止队列”，两者的差异必须用文字和图标说明，不能只靠颜色。

`accept="audio/*"` 只能改善选择器体验，不能当作安全验证。拖拽、MIME 为空、扩展名伪装和解析不匹配均由服务层给出清晰结果。

## 编辑体验

- 用户先选择导出目标，再编辑元数据。格式目录和表单能力配置是唯一的字段可编辑性来源，组件不得按照 `mp3`、`m4a` 或 `aac` 名称自行分支。
- 目标不支持编辑的字段保持可见，以便用户理解当前源文件内容；原生控件禁用，导出目标区和受影响分组附近显示持久的文字原因。不能仅隐藏字段、只使用灰色或只依赖 hover 提示。
- AAC 目标下，整个封面集合不可编辑：新增、替换、移除、类型选择和排序均禁用，已有封面仍可预览。说明应直接写明“ADTS AAC 不承载内嵌封面；请选择 MP3 或 M4A 以编辑封面”。
- 每个已改变的字段有非色彩的“已修改”提示，以及“恢复原值”操作。
- 用户从一个已填字段清空内容时，表示请求删除该标签，而不是读取失败。
- 封面区域是集合编辑器，支持增加、替换、移除、类型（front、back、disc、artist、other）和顺序管理，并为每张图提供可访问的替代文本状态和加载失败提示。选择入口附近明确展示“PNG、JPG/JPEG、GIF、WebP，最大 2 MB，1000×1000 px”。
- 替换封面时先校验文件大小、真实图片类型和尺寸，再创建预览。任一检查失败时保留原有有效封面及其他表单草稿，并在控件下方显示具体原因和当前值，不以 toast 代替错误说明。
- GIF 和 WebP 可作为封面候选，预览按浏览器能力呈现；导出预检必须说明目标格式能否保存每张封面、其类型和顺序。若容量受限，先让用户逐张决定保留或省略。
- 歌词是按语言分组的独立槽位列表，而不是合并的单一输入框。每个槽位都有可调整大小的“歌词原文”输入，始终完整保留时间标签、换行和空行，不能为预览方便而修改用户内容。
- 歌词区顶部提供“添加歌词槽位”。语言控件是可创建的下拉输入：按既定顺序提供未指定、中文、英语、日语、韩语等常用语言码，也可输入其他语言码；提交时必须小写化并检查重复。已有槽位的语言也可改选，但不能改成任何其他已存在的语言。
- 每张歌词槽位卡可单独编辑、恢复、删除。歌词槽位集合是新副本的最终歌词清单：删除某语言槽位会在导出时清除该语言所有已识别的源歌词标签，不保留隐藏的旧 `lyrics-{language}` 或原生歌词帧；没有任何歌词槽位时显示明确的空状态和添加入口。格式能力禁用歌词时，槽位内容仍可读，但新增、语言变更、编辑和删除全部禁用并在分组附近说明原因。
- 曲目号、碟号等数值字段用相邻的“编号 / 总数”组呈现，避免用户误解为一个自由文本。
- 表单失焦后进行局部校验；导出前进行完整校验。日期错误应说明问题和修复方式，例如“日期请使用 YYYY、YYYY-MM 或 YYYY-MM-DD”。

### 歌词预览与时间标签

每张歌词槽位卡在语言与原文编辑器之后提供自己的原生折叠“歌词预览”，默认收起；摘要说明预览类型，展开状态由明确的“展开/收起”语义和原生键盘行为提供。预览在导入、粘贴和停止输入后自动刷新，状态须使用文字说明，不能仅靠颜色区分。每个预览只呈现所属语言的内容，不能把不同语言文本串接到同一段落。

- 检测到 LRC 式时间标签时，使用时间轴列表：左侧为固定宽度、等宽数字的时间，右侧为歌词内容。每个时间标签都保留为独立时间轴行，即使同一行歌词有多个时间标签；歌词内容可以自然换行，不强迫挤在单行。
- 检测到混合内容时，带标签行按时间轴展示，未带标签的非空行作为“未标记内容”保留在相邻位置，并给出可见提示。不能因为它们缺少时间标签而丢弃。
- 未检测到有效时间标签时，使用纯文本预览，保留原有换行、连续空行和段落间距；长行按容器宽度换行，不能把多行歌词串接为单行。
- 无效或半写的时间标签保持原样显示，并提供不打断编辑的格式提示。解析失败不应阻止用户保存普通歌词。
- 时间轴预览的无障碍文本以“时间，歌词内容”的顺序朗读；切换预览模式只更新预览区域，不抢占输入焦点。

LRC 预览是阅读辅助而非播放进度条，也不是“同步歌词已成功写入文件”的承诺。每个槽位的原文编辑区与槽位集合是歌词的唯一数据源和最终导出清单。浏览器路径会清除已识别的源歌词标签或帧，再把第一个槽位写为普通 `lyrics` / `lyrics_language`，其他槽位尝试以 `lyrics-{language}` 写入；多个语言的播放器兼容性风险必须在预检中逐项说明。检测到原生 `SYLT` 时，预检说明浏览器不会生成新的同步歌词，导出会移除该已识别帧并以当前槽位的普通歌词为准；界面不得暗示它会生成或保留同步歌词。

## 导出体验

格式控件位于元数据表单之前，包含“保持原格式”和首发浏览器矩阵中的 MP3、M4A、AAC 三个明确目标；不显示自定义扩展名或其他 FFmpeg 格式。选定目标后，界面立即依据其表单能力配置更新字段状态，再进行完整预检。自定义目标属于相邻的“复制 FFmpeg 命令”本机路径，不能让用户误以为可由浏览器导出。

预检结果紧邻导出按钮显示，至少包括：输出扩展名、所选引擎、是否重新编码、编码质量预设、已知的元数据保留/丢失情况。选择 AAC 时显示实际输出为原始 ADTS `.aac`；若存在待保留或新增封面，预检逐张说明这些封面不会写入 AAC 副本。只有没有可执行浏览器目标、运行时不可用或表单无效时主按钮禁用；可生成副本但有字段损失、模糊写入、探测不完整或无法逐项验证时，主按钮在确认后可用并保留原有草稿。

当目标确实不能转换（没有可执行浏览器目标或运行时不可用）时使用上下文错误面板，不用只出现短暂 toast：

- 标题直接说明“此文件不能安全导出为 AAC”之类的事实。
- 内容解释具体限制，例如“原始 AAC 不承载内嵌封面，请改用 M4A 或 MP3”。
- 提供“改用 MP3”主建议。点击只更新格式和预检，不自动开始下载。
- 保留“返回格式选择”操作，绝不丢弃用户编辑。

导出中显示阶段性进度、可取消操作和“请保持此页面打开”的轻量提示。成功后显示默认 `{源文件名} (MINFO).{扩展名}` 输出文件名和“再次导出”入口；失败后恢复可编辑状态。源文件始终明确标注为“未修改”。

异步导出结果不能只放在页面顶部：全局状态以固定在左上角、可关闭的通知面板呈现，方便用户无论停留在哪个滚动位置都能看到任务结束；下载已开始、文件已加入和取消确认等短暂确认在 5 秒后自动关闭，进行中的状态和错误则保持可见，直至被替换或手动关闭。失败同时必须在导出按钮紧邻位置保留持久的错误摘要，说明未下载文件、草稿仍在，并在失败后把滚动位置和键盘焦点带到该摘要。该定位在 `prefers-reduced-motion` 下不得使用平滑滚动。全局通知使用温和播报，具体失败摘要使用唯一的紧急播报，避免重复朗读同一错误。

风险确认使用结构化面板，不使用笼统复选框：逐项列出每个受影响字段、封面和音频质量变化，支持键盘逐项选择，明确打开时和关闭后的焦点位置。确认控件的可见文字为“我已知晓，坚持导出”，并同时说明“仅生成新副本，源文件不会修改”。确认只绑定当前源文件身份、草稿版本、目标、运行时版本和风险清单；任一项变化后重新确认。已确认的风险允许继续尝试导出，但仍不绕过输出容器与音频流完整性验证；对于已确认的输入探测不完整或非首发源格式，界面要明确说明元数据无法逐项回读将不再取消副本下载。

“复制 FFmpeg 命令”位于导出按钮旁，提供 Bash/Zsh 与 PowerShell 两种脚本。它从同一导出计划生成，并提供源文件、输出文件和每张新增/替换封面图的本地路径字段。浏览器无法读取真实本地路径时使用可见占位符；复制的脚本会在 FFmpeg 前检测未替换占位符并给出修复提示，默认使用不覆盖模式。

## 无障碍与键盘标准

- 所有拖放功能都有文件选择器等价入口；所有操作可通过键盘完成。
- 禁用的原生表单控件不应成为唯一的信息承载点：控件附近的禁用原因必须可见并与该组关联；选择其他格式后，重新启用的控件按自然顺序恢复键盘可达性。
- 解析、预检、转换与下载结果通过恰当的实时区域播报，避免重复播报进度噪声。
- 错误出现后焦点移至错误摘要，摘要链接到对应字段。
- 可见焦点环、文字/背景对比度、按钮对比度均满足 WCAG AA；颜色从不单独表示成功、错误或已修改。
- 封面预览有有意义的替代文本或明确的“无封面”状态。技术缩写提供可见解释或可访问名称。
- 大文件或低性能设备上，界面保持可滚动和可取消，重型处理绝不阻塞主线程。

## 文案原则

文案用事实替代承诺：使用“正在检查能否导出”而非“正在智能转换”，使用“未能读取”而非“没有元数据”。格式失败优先说明发生了什么、如何继续和文件是否安全，避免直接暴露命令行日志。

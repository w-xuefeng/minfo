# 实施路线与验证计划

## 实现状态说明

阶段 A 与阶段 B 的基础代码已经落地；阶段 C 的运行时缓存、FFprobe/FFmpeg 服务接口和回读保护也已具备。浏览器运行时使用 pnpm 锁定的 `@ffmpeg/core@0.12.10` 与 `@ffmpeg/ffmpeg@0.12.15`，构建时生成资产哈希清单并可启用浏览器导出。当前 Actions 会运行冻结安装、依赖 Registry 签名校验、漏洞审计、格式、类型、lint、单元测试、构建和运行时清单审计；真实 Chromium MP3/M4A/ADTS AAC 样本回归仍是媒体能力持续验证项。活动任务的临时 OPFS 用户媒体工作区也仍待实现。

## 实施顺序

### 阶段 A：脚手架与质量基线

创建 Vite + Vue 3 + TypeScript + pnpm 项目，配置严格 TypeScript、格式化、lint、单元测试和 GitHub Pages 构建。配置 `main` push 触发的发布工作流：只有质量门槛全部通过才发布 `dist/`。`pages` 首次为孤儿分支，后续成功构建保留提交历史；另设手动回滚工作流指向既有验证提交。构建流程从 pnpm 锁定的 `@ffmpeg/core` 生成媒体运行时清单与每个 FFmpeg/FFprobe WASM 资产的 SHA-256；CI 验证全部已锁定依赖的安装完整性、Registry 签名与已知漏洞。此阶段先验证项目站点的 `base` 路径、静态资源和发布工作流。

完成条件：应用可在项目型 GitHub Pages URL 下刷新和加载资源；`main` 中的源码和 `docs/` 不会进入 `pages`；CI 通过冻结依赖安装、签名/漏洞审计、格式化、类型检查、lint、单元测试、构建和发布。媒体运行时必须通过版本、资产 SHA-256 与浏览器样本回归；前两项由构建强制执行，样本矩阵持续扩展。

### 阶段 B：领域模型与 UI 状态机

实现文件会话、顺序队列、元数据草稿、字段状态、导出目标、能力结果和任务状态机。使用假媒体服务锁定 UI 的空、拖拽、解析、成功、字段错误、格式不支持、转换中、取消、停止队列、风险确认、成功和失败状态。

完成条件：无媒体依赖时，所有交互状态可测试，替换文件、取消、暂停、失败和重新分析不会丢失应保留的逐项草稿。

### 阶段 C：轻量探测与原格式元数据路径

接入 File API、原生时长/AudioBuffer 技术属性读取和能力探测；明确其不能读取通用嵌入标签。实现页面启动后后台准备的 OPFS 媒体运行时缓存服务，覆盖缓存命中、版本升级、校验失败、同源重试、受控禁用、配额不足与临时任务工作区清理。接入受控浏览器标签解析器与 Worker 中的 `ffprobe` JSON 探测，优先完成 MP3、M4A 与 ADTS AAC 样本的读取。再实现 `ffmpeg` 驱动的可验证元数据写入/重封装路径，并记录字段保留行为。

完成条件：MP3、M4A 和 ADTS AAC 支持样本经过编辑、导出、重新导入后，标准字段和确认后的降级结果符合格式策略表；AAC 上存在待保留或新增封面时，预检列出会从副本省略的封面并在确认后导出；不支持或不可验证的字段被明确确认。

### 阶段 D：能力路由与转码

实现 WebCodecs 可用性探测、容器适配前置条件和 Worker FFmpeg WASM 后备。首发浏览器输出矩阵只包含 MP3、M4A 与 ADTS AAC：MP3 ID3v2.3、MP3 ID3v2.4、AAC-in-M4A、ALAC-in-M4A 和原始 ADTS AAC 都需覆盖读取/回读路径；固定覆盖 MP3/M4A → `.aac`、`.aac` → MP3/M4A，以及 ALAC-in-M4A → MP3（有损确认）。ADTS AAC 不承载内嵌封面，存在待保留或新增封面时必须列出省略项、取得确认后生成 AAC 副本。GitHub Pages 以单线程核心为基线，本地或具备跨源隔离的环境可加速为多线程。FLAC、WAV、Ogg、WMA、APE、AMR、MIDI、ALAC、OGA 与自定义扩展名不进入浏览器输出控件，只在本机命令路径中保留。

完成条件：每个宣称支持的“源格式 -> 目标格式”都有自动化或人工可复现的样本结果、元数据保留记录和失败降级路径。

### 阶段 E：性能、无障碍与发布

加入大文件资源提示、取消清理、键盘流、屏幕阅读器播报、明暗模式、浏览器矩阵、本机 FFmpeg 脚本渲染与运行时来源/完整性材料。歌词以按语言唯一的槽位管理器呈现，预览默认折叠；`SYLT` 生成与逐帧/字节级验证不在本项目范围，只有普通歌词字段和 LRC 阅读预览进入该阶段。

完成条件：达到本文件的测试门槛，无已知阻塞错误后发布。

## 发布门槛

1. 只将通过端到端样本验证的格式标为“完整支持”。
2. 类型检查、lint、单元测试、构建和格式回归全部通过。
3. 所有失败路径均具有用户可理解的说明、恢复操作和草稿保留行为。
4. 不存在源文件上传、隐式网络媒体请求或将私人标签写入遥测的路径。
5. 项目站点在 GitHub Pages 仓库子路径下正常工作，发布源为由 Actions 管理、首次孤儿创建且后续保留成功构建历史的 `pages` 分支。

## 当前开放决策

- 首发浏览器输出矩阵已固定为 MP3、M4A、ADTS AAC；FLAC、WMA、APE、AMR、Ogg、WAV、MIDI、ALAC、OGA 与自定义目标的可行性只属于本机命令路径，不因当前 WASM 的任何能力而重新出现在浏览器控件中。许可证标签不是拒绝条件；运行时包版本不得使用 `latest`、`^` 或 `~`，且必须通过冻结锁文件、Registry 签名、漏洞审计和资产哈希校验。
- 音频文件的资源告警阈值和单文件处理上限必须由性能测试决定；封面替换的首版保护阈值已固定为 PNG、JPG/JPEG、GIF、WebP，最大 2 MB（2,000,000 bytes）和 1000×1000 px。
- `SYLT` 的生成、逐事件语义和字节级保真验证已明确移出路线图，但已识别的 `SYLT` 不再属于未受管理的保留内容。当前承诺按语言独立管理原文普通歌词：槽位集合是最终导出清单，导出先清除所有已识别歌词标签或帧，再以第一个槽位的 `lyrics` / `lyrics_language` 与其余槽位的 `lyrics-{language}` 写入。删除某槽位必须移除对应旧歌词；已验证浏览器路径回读当前标签并验证已清除源标签不再存在，失败则取消下载。视觉时间轴预览默认折叠；含原生 `SYLT` 的文件会说明其将被移除，当前槽位内容只作为普通歌词导出。
